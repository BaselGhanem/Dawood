# نظام ERP عربي لإدارة الزيوت المحروقة والبضاعة والمخزون والتصنيع والمبيعات والصندوق

## الملفات الرئيسية
- `login.html` تسجيل الدخول.
- `dashboard.html` لوحة تحكم تشغيلية.
- `admin.html` المستخدمون والصلاحيات وسجل الحركات.
- `warehouse.html` المستودعات، تحميل السيارات، الإرجاع، الجرد وفروقات النقص.
- `manufacturing.html` وصفات التصنيع وأوامر الإنتاج.
- `sales.html` فواتير البيع، العملاء، الذمم والتحصيل.
- `purchases.html` فواتير الشراء، الموردون وذمم الموردين.
- `finance.html` تسليم النقد، التحويلات، السلف، الرواتب ومصاريف السيارات.
- `reports.html` تقارير قابلة للفلترة والتصدير.
- `employees.html` دليل الموظفين وكشف الموظف.
- `settings.html` إعداد الشركة وFirebase والنسخ الاحتياطي والاستيراد.

## التشغيل المحلي
افتح `login.html` مباشرة أو عبر Live Server. عند عدم وجود إعداد Firebase محفوظ، يعمل النظام بوضع محلي آمن للتجربة داخل المتصفح.

بيانات الدخول المحلية:
- البريد: `admin@erp.local`
- كلمة المرور: `Admin2026@`

## إعداد Firebase
1. أنشئ مشروع Firebase.
2. فعّل Authentication بطريقة Email/Password.
3. أنشئ Cloud Firestore.
4. انسخ إعدادات تطبيق الويب من Firebase Console.
5. افتح `settings.html` بعد الدخول المحلي.
6. أدخل قيم Firebase في نموذج إعداد Firebase واحفظها.
7. أعد تحميل الصفحة.
8. انشر قواعد Firestore الموجودة في `firestore.rules`.
9. من صفحة الإعدادات اضغط "تهيئة بيانات أساسية" لإضافة Seed Data.

## النشر على Firebase Hosting
```bash
firebase login
firebase init hosting firestore
firebase deploy
```
استخدم `.` كمجلد النشر إذا كان المشروع داخل الجذر الحالي، أو انقل الملفات لمجلد hosting الذي تختاره.

## ملاحظات أمنية مهمة
- الواجهة تطبق صلاحيات حسب الدور وتخفي الأزرار غير المصرّح بها.
- قواعد Firestore تمنع القراءة والكتابة غير المصرّح بها.
- الحذف في النظام حذف ناعم Soft Delete، ولا يتم حذف السجلات الحرجة نهائياً من الواجهة التشغيلية.
- جميع الحركات المهمة تُسجل في `systemLogs`.
- إنشاء مستخدم Firebase Auth من الواجهة يتم عبر REST API عند توفر إعداد Firebase، ثم يتم إنشاء ملف المستخدم في Firestore.

## Seed Data
تتضمن البيانات الأساسية:
- مدير نظام.
- داود.
- معتصم.
- مندوب تجريبي.
- مستودع رئيسي.
- مستودع سيارة.
- أصناف مواد خام ومنتجات مصنّعة وبضاعة جاهزة وأدوات.
- وصفة تصنيع.
- عميل تجريبي.
- موردين تجريبيين.

## الميزات المنفذة
- RTL كامل وخط Almarai.
- تصميم SaaS عربي Premium متجاوب.
- دعم 360px و390px و430px و768px واللابتوب والديسكتوب.
- جدول داخل حاوية Scroll داخلي فقط.
- صلاحيات حسب الدور والصفحة والإجراء.
- إدارة المستخدمين وتعطيلهم وتعديل أرصدتهم ورواتبهم.
- إدارة المستودعات والأصناف والرصيد حسب المستودع.
- تحميل سيارة مندوب من المستودع الرئيسي.
- إرجاع بضاعة من سيارة المندوب للمستودع الرئيسي.
- جرد سيارة مندوب واحتساب النقص كسلفة على المندوب.
- وصفات تصنيع واستهلاك مواد خام وزيادة المنتج النهائي.
- فواتير مبيعات نقدية وآجلة.
- دفتر ذمم العملاء والتحصيل نقداً أو CliQ.
- فواتير مشتريات نقدية وآجلة.
- ذمم الموردين وتسجيل الدفعات.
- تسليم النقد إلى داود أو معتصم مع تأكيد/رفض.
- تحويل داخلي بين المستخدمين.
- سلف ورواتب وكشف موظف.
- مصاريف سيارات وصيانة وأدوات.
- تقارير عامة مع فلاتر تاريخ وبحث وتصدير CSV.
- سجل حركات Audit Trail.
- نسخ احتياطي JSON واستيراده.
- استيراد CSV للمجموعات.
- وضع داكن/فاتح وتخصيص اسم الشركة واللون.

## QA Checklist
- تسجيل الدخول المحلي يعمل.
- حفظ إعداد Firebase ثم إعادة التحميل ينتقل للوضع السحابي.
- لا يوجد Horizontal Scroll على مستوى الصفحة في الموبايل.
- النماذج تتكدس عمودياً على الموبايل.
- الجداول داخل `.table-wrap` فقط.
- اعتماد تحميل سيارة ينقص الرئيسي ويزيد السيارة.
- اعتماد بيع ينقص مستودع البائع.
- البيع الآجل ينشئ ذمة عميل.
- التحصيل يخفض الذمة ويزيد رصيد المندوب.
- الشراء يزيد المخزون.
- الشراء الآجل ينشئ ذمة مورد.
- تسليم النقد يبقى Pending حتى تأكيد داود/معتصم.
- جرد السيارة يسجل النقص كسلفة.
- التصنيع يستهلك المواد الخام وينتج المنتج النهائي.
- سجل الحركات يسجل الإضافة والتعديل والحذف الناعم والحركات المالية.
- التصدير يعمل من التقارير والصفحات التشغيلية.
